# System Audit & Baseline Measurements (September 2026)

Background research and measurements behind the AMDXSS Engine power profiles.
Test machine: Ryzen 7 5700G (Cezanne APU, Radeon Vega iGPU), B550M board,
2x8 GB DDR4-2666 dual channel, NVMe SSD, Windows 11 25H2. All numbers below
were measured on that machine unless marked as assumption.

## 1. Key findings

**Finding A — stock plan locked minimum processor state at 100%.**
The pre-existing "Ultra Performance" style plan set `PROCTHROTTLEMIN=100%`,
pinning idle clock at ~3.999 MHz average. Dropping the minimum to 5% is the
single biggest Windows-side power saver.

**Finding B (root cause) — C-States disabled in firmware.**
The firmware exposes only 1 idle state (evidence: `Kernel-Processor-Power`
event ID 55 reports "1 state(s)"; `powercfg /energy` shows
`Idle State Count: 1`, `Lowest Performance: 62%`). No Windows tuning can
deep-idle the CPU while this holds; the big idle-power win requires enabling
Global C-State Control in BIOS. Even the Power Saver plan floored at ~3.3 GHz.

**Finding C — frequency counters lie on this build.**
`\Processor Information(*)\Processor Frequency` reports a constant nominal
3801 MHz on all cores. Comparisons below use `% Processor Performance x
3801 MHz`, which is consistent for plan-to-plan comparison.

## 2. Measured results (idle, real-world load: call + browser + tools)

| Configuration | Idle avg | Bench ST (iter/s) | Bench MT (iter/s) |
|---|---|---|---|
| Stock-like plan (min 100%) | 3.999 MHz | 23,204,975 | 180,684,107 |
| Eco (min 5%, Efficient boost) | 3.488 MHz (-12.8%) | 23,354,515 (+0.6%) | 181,215,490 (+0.3%) |
| Balanced (min 5%, Enabled boost) | 3.553 MHz (-11.2%) | 23,413,989 (+0.9%) | 180,624,481 (+-0%) |

No measurable performance regression (all within +-1% noise) while idle
clock and power dropped. Power-saver probe and per-core audit confirmed the
"cannot deep idle" pattern on all 16 threads.

## 3. Power math

Dynamic CMOS power: `P ~= C * V^2 * f`. Because core voltage drops with
frequency, power savings always exceed clock savings:

| Voltage assumption | Balanced | Eco |
|---|---|---|
| V constant | -11.2% | -12.8% |
| V proportional to sqrt(f) | -21.1% | -23.9% |
| V from Zen 3 curve (~1.10V@4.0GHz -> ~1.00V@3.55GHz) | ~-26.6% | ~-29.4% |

Thermal: ΔT = P x R_th, so the temperature rise above ambient drops by roughly
the same ~27% under equal load — quieter fans at light load.

Memory bandwidth (matters for the iGPU): 2666 MT/s dual-channel = 42.7 GB/s;
3200 MT/s = 51.2 GB/s (+20%), worth roughly +5-15% iGPU fps after enabling
EXPO/XMP.

## 4. Windows powercfg quirks found while building (troubleshooting reference)

1. `powercfg /setacvalueindex` silently fails (exit 0, value not stored) for
   hidden settings not yet present in the scheme (`PERFBOOSTMODE`,
   `SYSCOOLPOL`). Unhide first: `powercfg /attributes SUB_PROCESSOR <ALIAS>
   -ATTRIB_HIDE`, then set. `setup_schemes.ps1` handles this with retry and
   readback verification.
2. The OS "power mode" slider is an overlay scheme: `powercfg /setactive
   OVERLAY_SCHEME_MIN` is valid and effective, but `/overlaysetactive` (shown
   in the help title) rejects commands on this build. Restoring = simply
   `powercfg /setactive <normal scheme>` (verified: `ActiveOverlayAcPowerScheme`
   back to zeros).
3. Parse `powercfg /q` output per setting block, not with a global regex —
   the format differs between builds.

## 5. Post-BIOS checklist (requires restart — not done yet)

1. BIOS: Global C-State Control = Enabled/Auto; CPPC + CPPC Preferred Cores =
   Enabled. This unlocks the big idle-power win.
2. BIOS: EXPO/XMP to DDR4-3200 (fallback 2933 if unstable).
3. Update B550 chipset driver (SMBus/PSP on the test machine were 2020-2022).
4. Adrenalin: reset to defaults / re-enable power-gating flags, use Radeon
   Chill FPS caps instead of uncapped modes.
5. Re-measure: idle should drop well below 2.5 GHz at true idle; performance
   should hold.
